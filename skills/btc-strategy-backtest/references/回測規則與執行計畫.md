# 回測規則與執行計畫

## 1. 目的與界線

評估找策略系統的候選，不承諾找到盈利策略。研究上游產生同名py/JSON且源審查approved、db_committed=true，才能回測。Codex不把源碼修改混入回測。程式、資料、規格、成本和政策都需有可追查版本。

## 2. 固定政策

policy=net_btc_cumulative_50_v1。validation/test各 return_pct≥50、trade_count≥30、profit_factor≥1.1、sharpe_ratio≥0.5、drawdown_pct≤15。三test folds至少兩return_pct>0，cost_stress return_pct>0。50%為BTC計價累積淨值收益，不是USD、年化、某一最好子段或訓練收益。

原始引擎policy的缺欄位fallback不對所有指標顯式檢查NaN；verify_result新增finite audit，若audit與引擎不一致一律阻擋公告。audit只驗數值門檻，來源審查/程式及資料hash仍須另核對。

qualified為歷史研究驗收。paper_ready另要求資料stale_days≤2且funding_included；其true也不授權啟動紙上或實盤。源審查failed不能合格。

## 3. 資料與七組评估

train第一根有效行情至2024-01-01 UTC前；validation從2024-01-01至2025-01-01前；test從2025-01-01到實際快照尾。native timeframes 5m/15m/30m/1h/4h。起點實際約2020-08，不是完整2020；不得補稱資料不存在的時間。

load_data要求OHLCV數值有限、正價格、非負量；去完全相同重複timestamp，衝突重複拒絕；時間對齊/間隔與缺口依引擎核對。各段至少max(300,warmup*2)根；warmup至少50。實際快照保存資料hash、funding hash、timestamp起訖、筆數、gaps與staleness。

因果檢查在訓練尾窗口執行，整份資料僅執行凍結策略。每段重新模擬持倉，不把訓練期持倉跨到驗證；test folds按K線筆數切成三份，非固定年。

train/validation/test有ledger及曲線；test_fold及cost_stress目前只有metrics，trades/equity为空。不能宣稱每個split都有完整交易紀錄。

## 4. 成交與成本

使用Binance COIN-M BTCUSD_PERP，inverse/BTC計價，部位fraction0.3；fee每側0.001、entry slip0.0004、exit slip0.0006、roundtrip spread0.0002。這些是目前研究假設，不是已查證帳戶實際费率。環境變數可覆寫，報告須核對cost_model，不只信預設。

訊號收盤決策、下一根開盤成交；停損/止盈採既有bar high/low觸發。逆合約損益、持倉浮動淨值、資金費率及每日Sharpe按engine計算。intrabar無成交順序及訂單簿，ambiguous_bars須揭露。反轉可能被just_closed延後，不能稱與Pine相同。

資金費率時間按K線open bucket對齊，行情open近似mark price；資料完整性採funding manifest覆蓋，沒有完整覆蓋必须披露。cost stress將fee/slip/spread乘1.5；資金費率不是任意乘1.5。

## 5. 執行順序與驗收

health/inspect → 找未完成且已提交候選 → 来源/spec/hash/政策及資料檢查 → 共用鎖run → result摘要與独立audit → 檢查完整曲線、交易與archive → Supabase七split/快照核對 → 保存本地state → 指定通知。

每輪只一候選；結果不存在不能判完成。lock busy/no candidates也會正常返回，必須實查。ValueError等技術拒絕會生成.rejected.json並移Rejected，不是完整績效。RuntimeError可能保留候選待診斷。

## 6. 防擬合

參數、週期只用訓練與驗證選，測試前凍結，保存全部試驗。測試後改參數是新變體，這段歷史已被使用，不能再稱獨立holdout。已查看2025–2026，不構成新獨立證明。再通過也需向前觀察，無任何自動下單。
